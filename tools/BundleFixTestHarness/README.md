# Bundle Fix Test Harness (dev-only)

Перевіряє фікс назв клунків **без Content Patcher і без справжнього мовного пака**.
У релізи не входить, на Nexus не публікується.

Харнес вдає пак, який гейтить переклад клунків станом сейва: реєструє мод-мову `test`
і, поки ввімкнена «умова пака», віддає `Data/Bundles` з маркером `[TEST] ` у полі 6.
Ключове — **харнес сам нічого не інвалідує**: так поводиться пак із дефолтним update-rate CP
(`OnDayStart`). Тобто харнес не допомагає фіксу, а перевіряє, чи той закриває цю прогалину.

Поле 0 харнес не чіпає: якби чіпав, `UpdateBundleDisplayNames()` не зматчив би бандл
і фікс тихо нічого не робив би. Та сама вимога стосується справжніх паків.

## Збірка

Потрібні ті самі `src/CustomLanguageBundleFix/libs/` (див. README репо, розділ Building):

```bash
cd tools/BundleFixTestHarness && dotnet build -c Release
```

## Підготовка

1. SMAPI 4.x у теку гри.
2. `releases/CustomLanguageBundleFix-1.1.1.zip` розпакувати в `Mods/`.
3. Створити `Mods/BundleFixTestHarness/` і покласти туди `manifest.json`
   та `bin/Release/net6.0/BundleFixTestHarness.dll`.

## Команди в SMAPI-консолі

| Команда | Що робить |
|---|---|
| `bft_on` / `bft_off` | увімкнути/вимкнути «умову пака». Асет НЕ інвалідується — навмисно |
| `bft_names` | мова, локація і назви клунків так, як їх бачить гра |
| `bft_warp` | телепорт до Ремісничої кімнати (тригер фікса) |
| `bft_invalidate` | інвалідувати `Data/Bundles` вручну — самоперевірка харнеса |

## Прогін A — фікс працює

1. Запустити через SMAPI. На титулці кнопка-глобус → вибрати рожевий прямокутник (мова `test`).
   **Це обовʼязково**: усе в моді гейтнуте на `LanguageCode.mod`.
2. Завантажити сейв.
3. `bft_names` → чекаємо `мова: mod / пак-код: test` і `назв із маркером: 0/N`.
4. `bft_on` — умова ввімкнена, нічого не інвалідовано.
5. `bft_names` → все ще `0/N`. Це і є прогалина, яку закриваємо.
6. Зайти до Ремісничої кімнати — пішки або `bft_warp`.
7. `bft_names` → чекаємо **`назв із маркером: N/N`**. Це і є пройдений тест.
8. У `%APPDATA%\StardewValley\ErrorLogs\SMAPI-latest.txt` має бути trace нашого мода
   `Bundle names rebuilt after asset update.` (у консолі trace видно лише з
   `"VerboseLogging": true` у `smapi-internal/config.json`).

## Прогін B — контроль, без фікса

1. У `Mods/CustomLanguageBundleFix/config.json` поставити `"BundleNamesFix": false`, перезапустити.
2. Повторити кроки 1–6 прогону A.
3. `bft_names` → мусить лишитися `0/N`: без фікса вхід до кімнати не дає нічого.
4. Вийти в меню і завантажити сейв знову → `bft_names` покаже `N/N`. Ванільна гра підхоплює
   переклад лише при завантаженні — той самий ритуал «збережись і перезайди».

Без прогону B тест нічого не доводить: `N/N` могло б зʼявитися й саме собою.

## Якщо прогін A дав `0/N` на кроці 7

Спершу `bft_invalidate`, тоді `bft_names`:

- маркер зʼявився → харнес живий, ламається тригер фікса (`Player.Warped` /
  перевірка `Game1.currentLocation is CommunityCenter`);
- маркер не зʼявився → ламається сам харнес, до фікса претензій нема.
